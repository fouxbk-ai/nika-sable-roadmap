# Блок 12. Сайт-роадмап Nika Sable с диаграммой Ганта

**Источник:** Запрос пользователя 2026-05-15 — визуальный сайт, где видно дорожную карту проекта и автоматически отражается прогресс по мере закрытия задач в vault.

## Контекст

Задачи проекта nika-sable лежат в `30-Проект/задачи-для-кодекса/*.md`. У каждой — frontmatter с `блок`, `status`, `зависит-от`, `created`, и тело с чек-боксами `- [ ]` / `- [x]`. Сейчас прогресс виден только через чтение файлов по очереди. Нужен одностраничный сайт, который:

1. Парсит эти `.md`-файлы (источник истины — vault, не отдельная база).
2. Рендерит стильную диаграмму Ганта с задачами по оси Y и временем по оси X.
3. Показывает прогресс каждой задачи (по доле закрытых чек-боксов) и общий прогресс роадмапа.
4. Рисует стрелки зависимостей между блоками (из поля `зависит-от`).
5. Перестраивается автоматически при коммите в репозиторий (CI build) и доступен по публичной ссылке.

## Стек (обязателен, без альтернатив без согласования)

- **Astro 4.x** — статический сайт, минимум JS, идеально для контентных страниц с одной интерактивной зоной.
- **TypeScript** во всех скриптах.
- **Tailwind CSS 3.x** — стилизация.
- **gray-matter** — парсинг frontmatter.

- **pnpm** как менеджер пакетов.

## Источник данных и модель

Парсер должен идти по `../30-Проект/задачи-для-кодекса/2026-*.md` (относительно `site/`). Игнорировать `README.md`.

Из каждого файла извлекать:

```ts
type TaskBlock = {
  id: string;            // имя файла без расширения
  block: number;         // frontmatter.блок
  title: string;         // H1 из тела
  status: 'открыта' | 'в работе' | 'выполнена' | 'сделана' | 'заморожена';
  dependsOn: number[];   // frontmatter.зависит-от → массив номеров блоков
  created: string;       // ISO
  start?: string;        // ISO, опционально из frontmatter
  due?: string;          // ISO, опционально из frontmatter
  totalCheckboxes: number;
  doneCheckboxes: number;
  progress: number;      // doneCheckboxes / totalCheckboxes, 0 если total=0
  vaultPath: string;     // путь относительно корня vault для obsidian://-ссылки
};
```

**Нормализация статусов:** `сделана` и `выполнена` — синонимы, считать обе как `done`. Для UI ввести enum `Status = 'todo' | 'in_progress' | 'done' | 'frozen'`.

**Парсинг `зависит-от`:** поле в frontmatter — массив строк вида `"блок-5"`. Извлекать число регуляркой `/блок-(\d+)/`.

## Логика расписания (`schedule.ts`)

Поскольку у большинства задач нет `start`/`due`, рассчитываем их так:

1. Если в frontmatter есть `start` — берём как есть. Если есть `due` — берём как есть.
2. Иначе делаем топологическую сортировку по `dependsOn`.
3. Базовая длительность блока — 1 день. Если блок в статусе `done` — длительность = `max(1, created → дата последнего изменения файла)`.
4. `start` блока = `max(due всех зависимостей) + 1 день`; для корней (без зависимостей) `start = min(created по всем блокам)`.
5. `due = start + duration`.
6. Все вычисленные даты помечаются флагом `inferred: true` для UI (рисовать пунктиром).

При обнаружении цикла в зависимостях — падать на этапе build с понятной ошибкой.

## Визуал Ганта (это ключевая часть, не упрощать)

**Сетка и оси:**
- Ось X — время, формат `D MMM` (локаль ru-RU), вертикальные линии на каждый понедельник.
- Сегодняшний день — вертикальная красная линия с подписью «сегодня» наверху.
- Ось Y — блоки сверху вниз по возрастанию номера. Высота строки 44px.

**Полоски задач:**
- Скруглённые прямоугольники (rx=6), высота 28px.
- Заливка градиентом от тёмного к светлому варианту цвета статуса.
- Внутри полоски — заполненная часть `progress` (более тёмная), процент текстом справа от полоски.
- Полоски `inferred` — обводка пунктиром, заливка прозрачнее.

**Цвета статусов (тёмная тема по умолчанию):**
- `todo` — slate-500 (`#64748b`)
- `in_progress` — amber-500 (`#f59e0b`)
- `done` — emerald-500 (`#10b981`)
- `frozen` — zinc-700 (`#3f3f46`)

**Зависимости:**
- Стрелки между блоками: кривая Безье от правого края предка к левому краю потомка, цвет — текущий статус потомка, толщина 1.5px, маркер-стрелка на конце.
- Стрелки не должны пересекать текст; если две стрелки накладываются — небольшое смещение.

**Интерактив:**
- Ховер на полоске — тултип с заголовком, статусом, прогрессом, датами, списком зависимостей.
- Клик на полоске — открывает `obsidian://open?vault=Obsidian%20Vault&file=<vaultPath>` в новом окне.
- Кнопки зума `+ / − / fit` в правом верхнем углу графика.

### Риски и решения заранее

- **Astro не сможет читать файлы выше `site/`.** Использовать Node `fs` на build-time, не `fetch`, и аккуратно строить путь через `path.resolve(process.cwd(), '..', '30-Проект', ...)`.
- **Русские ключи frontmatter могут быть неудобны в TypeScript.** Читать их через bracket-notation: `data['зависит-от']`, `data['блок']`.
- **Чек-боксы могут быть вложенными.** Считать все task list items в AST, независимо от уровня вложенности.
- **У задач без чек-боксов прогресс будет 0%.** Это ожидаемое поведение по спеке; не считать такие задачи выполненными только по статусу.
- **Obsidian URL с кириллицей может ломаться.** Кодировать `vaultPath` через `encodeURIComponent`, но не кодировать весь URL целиком.
- **GitHub Pages может требовать base path.** Если репозиторий деплоится не в root-домен, добавить `site`/repo `base` в `astro.config.mjs` отдельной правкой после проверки Pages URL.

### Порядок коммитов
